NoSQL Data Modeling

MongoDB Embedded Document Pattern (Subdocuments)

In modern NoSQL database design, data that is accessed together should be stored together. Airvoyage implements the Embedded Document Pattern (Denormalized Subdocuments) to eliminate multi-table relational joins, ensure atomic single-document writes, and guarantee flight history immutability.

Why Embed Instead of Reference?

  • 1-to-Few Bounded Cardinality: A single booking contains between 1 and 9 passengers. It will never grow unbounded, making it the textbook scenario for array embedding.
  • Zero JOIN Latency (O(1) Document Fetch): In SQL, fetching a booking with passengers requires querying two tables (flights_booking and flights_passenger) linked by foreign keys. In MongoDB, a single findOne() read fetches the booking and all passenger subdocuments in one disk seek.
  • Atomic Single-Document Transactions: Any updates to a booking and its passenger seats occur atomically within the single document boundary without requiring distributed 2-phase commits.
  • Snapshot Immutability: External flight APIs continuously update gate, terminal, and status. By embedding a frozen snapshot at booking time, passenger tickets remain immutable records for travel audits.

Implementation in Code: flights/flask_models.py

When a booking is confirmed, the system creates embedded subdocuments for each passenger with unique ObjectIds and embeds both the route details and passenger array inside the primary booking document: 

# 1. Construct embedded subdocuments for each passenger
pax_embedded = [
    {
        "_id": ObjectId(),
        "first_name": p["first_name"],
        "last_name": p["last_name"],
        "seat_number": p["seat_number"],
        "boarding_zone": p["boarding_zone"],
        "sequence_number": p["sequence_number"]
    }
    for p in passengers_data
]

# 2. Insert single denormalized document into MongoDB
booking_doc = {
    "_id": ObjectId(),
    "reference": "AV-7F9B10",
    "contact": {"email": contact_email, "phone": contact_phone},
    "passengers": pax_embedded,  # <--- Embedded Document Array!
    "route": {                  # <--- Embedded Route Subdocument!
        "origin": {"iata": "DEL", "airport": "Delhi", "gate": "41A"},
        "destination": {"iata": "BOM", "airport": "Mumbai"}
    }
}
db.flights_booking.insert_one(booking_doc)
Hybrid Database Architecture

Dual-Backend Hybrid Engine: MongoDB Atlas + SQLite Fallback

Airvoyage is built with industrial resilience. It utilizes a Polyglot Database Abstraction Layer that automatically detects cloud MongoDB Atlas availability while providing transparent, instant fallback to persistent SQLite (db.sqlite3).

Automated Resilience Pipeline

  1. Startup Probing: The application executes a fast non-blocking ping command against MongoDB Atlas with a strict 5000ms timeout.
  2. IPv4 DNS Resilience & TLS 80 Handshake Protection: Atlas clusters do not support IPv6/NAT64. The service patches Python's socket.getaddrinfo to prefer IPv4 and configures DNS resolvers (8.8.8.8) to prevent Windows DNS resolution errors.
  3. Transparent Switchover: If Atlas is offline or the client IP is not yet whitelisted (TLS Alert 80), all operations transparently route to the persistent SQLite relational database without dropping user requests.
  4. Data Layer Compatibility: The User, Booking, and Passenger adapters normalize dictionary keys across both BSON (_id) and SQLite (id), providing 100% template consistency.

Algorithmic Travel Tech

Cabin Matrix Layout & 2D QR Boarding Pass Engine

A full-stack implementation of airline seating ergonomics and digital boarding pass generation compliant with IATA barcoding principles.

Algorithmic Boarding Zones

Passengers are assigned sequential boarding zones based on seat location heuristics:

  • Zone 1 First & Business Class: Priority boarding at the front of the aircraft.
  • Zone 2 Premium Economy & Rear Window Seats: Early boarding to prevent aisle congestion.
  • Zone 3 Mid-Cabin Window & Middle Seats: Efficient progressive boarding.
  • Zone 4 Aisle Seats & Forward Cabin: Final general boarding call.

Digital Vector Boarding Pass PDF

Generated on the fly using Python's ReportLab graphics library:

  • 2D QR Code Generation: Dynamically encoded with passenger PNR, flight reference, date, and security checksum via generate_qr_data_uri.
  • High-Resolution Vector Graphics: Scalable vector geometry for airline logos, barcode striping, and tear-off stub layout.
  • Zero Storage Footprint: Generated in-memory via io.BytesIO streams and piped directly to the client browser as a downloadable PDF.
Security Architecture

Security Architecture & Cross-Framework Password Hashing

Enterprise security controls ensuring safe user authentication across dual backends and strictly isolating third-party credentials.

🔒

Dual Password Verification

Supports verification across both Django PBKDF2 SHA-256 hashes and Werkzeug Scrypt hashes, allowing seamless user logins across Flask and Django environments.

🛡️

Credential Isolation

Sensitive API keys (RapidAPI, MongoDB Atlas URIs) reside strictly in server-side .env files and are never passed to HTML templates or client-side JavaScript.

🔑

Session Integrity & CSRF

Cryptographically signed session cookies with HttpOnly flags and CSRF token protection on all state-altering POST routes.
